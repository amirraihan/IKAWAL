Use Cases & Pipeline — SmartDepot
Banduan Dagang Monitoring & Decision Support

One monitoring system for foreign detainees (banduan dagang) under remand, built on the existing BPK / Iringkawal reman register. Four use cases: a live interactive dashboard, case decision support (automated reman + risk priority), depot population forecasting, and an AI insight & automated report generator. Every time a reman record is keyed in or updated, the reman countdown, risk label, recommendation and dashboard refresh automatically.

Use cases: UC-1 … UC-4 Dataset: 14 columns · 2,115 rows (dummy) · Jan–Dec 2026 · depots DIKK, DIP Status: Draft v3

1. Purpose & Scope

The problem, then how the requested functions map to four use cases.

The reman register is kept as one Excel sheet per period, updated by hand. Reman end dates are tracked by eye, there is no consistent way to see which cases need action first, overcrowding is noticed only when a depot is full, and briefings and the monthly report are rebuilt each cycle. SmartDepot replaces the sheet with a structured entry form and a live dashboard over a small shared AI core.

3. The System at a Glance

One observable sentence, then the solution elements.

An officer keys in a new reman (or uploads the Excel); the system validates and cleans it, logs it as an event, recomputes the case fields, and re-runs the reman engine, risk scoring and decision support for that case — then refreshes the interactive dashboard and sends any alert. Each morning the population forecaster updates; on the 1st of each month the report generator produces the monthly report. All AI output is advisory; officers decide.

UC-2  Case Decision Support — Automated Reman + Risk Priority (per banduan dagang)

ProblemReman end dates are watched by eye and can be missed; there is no consistent way to see which cases need action first, or what that action should be.
ActorsInvestigating officer (NAMA PEGAWAI); depot head; legal unit.
InputsReman period, NO.REMAN, KESALAHAN, TINDAKAN, CATATAN flags, UMUR, DEPOT; later TARIKH TANGKAP, STATUS KES, DOKUMEN, extension count.
ApproachThree steps in one chain, on every save and every morning:
  1. E5 Automated reman — days left to tarikh_reman_tamat per banduan dagang; alerts to the named officer at 3 days, 1 day, due today and overdue; pre-filled draft extension or outcome paperwork.
  2. E6 Risk scoring — score 0–100 → Kritikal Tinggi Sederhana Rendah with top reasons (table 5.2). v2 adds an ML probability that the case will need an extension, once outcome history exists.
  3. E7 Decision support — one recommended next action (table 5.3); officer accepts or overrides; overrides are logged.
OutputsReman tracker, priority worklist per officer and depot, recommended action, draft paperwork (DOCX / PDF), daily alert.
KPIsReman reaching end date with no TINDAKAN (target 0) · % Kritikal actioned within 24 h · recommendation acceptance rate.
StatusPlanned v1 rules  v2 ML  Officer approves & submits; the system never files automatically

UC-3  AI Depot Population Forecasting

ProblemIntake surges and overcrowding are noticed only after they happen.
ActorsHQ operations; depot heads.
InputsNow: daily new reman per DEPOT (from reman start date); FAIL batches (operations). Later: TARIKH USIR / KELUAR and depot capacity.
ApproachE8 Stage A (current data): forecast weekly new-reman intake per depot for the next 4–8 weeks (moving-average baseline → SARIMA / Prophet / gradient boosting on lag + calendar features) — the 11 months in the sample are enough to start. Stage B (after exit dates are captured): headcount = previous headcount + intake − exits, forecast with a confidence band and a capacity warning.
OutputsIntake forecast per depot (Stage A); headcount and occupancy forecast with warning list (Stage B); capacity signal to UC-2.
KPIsForecast error (MAPE) · days of warning before a capacity breach.
StatusPlanned v1 Stage A  v2 Stage B
